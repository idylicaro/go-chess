# Lab 3.0-A: null move, LMR e futility pruning

Issue #44. Resultado: **as três técnicas passaram no SPRT, cada uma contra a versão anterior: null move +85,7 ± 33,2 Elo, LMR +100,2 ± 36,8 e futility +35,3 ± 19,6. Somadas, são cerca de +220 Elo sobre o alpha-beta sem poda.**

## Critério

Cada técnica entra só se um SPRT contra a versão sem ela aceitar H1, com elo0 = 0, elo1 = 10, α = β = 0,05.

## Método

As três ficam em `internal/search/pruning.go`, cada uma com uma chave em `search.Pruning` e uma opção UCI (`NullMove`, `LMR`, `Futility`). Assim o mesmo binário joga contra ele mesmo com uma técnica desligada, e a diferença entre os lados é só essa técnica.

- **Null move**: se a posição ainda fica ≥ beta depois de passar a vez e buscar com profundidade reduzida em R = 2 + profundidade/3, o nó é cortado. Não roda em xeque, logo depois de outro null move, com só rei e peões (zugzwang) nem com beta em zona de mate.
- **LMR**: lances quietos que não dão xeque, a partir do quarto lance do nó e com profundidade ≥ 3, são buscados primeiro com redução de 0,75 + ln(prof.) · ln(índice) / 2,25 e janela nula. Se passam de alpha, são buscados de novo em profundidade cheia.
- **Futility**: a 1 ou 2 plies do horizonte, fora de xeque, se a avaliação estática + 150 (ou + 350) ainda não alcança alpha, os lances quietos que não dão xeque são pulados.

Os testes ficam em `pruning_test.go`: com cada combinação a busca ainda acha o mate em 1, o mate em 2, ganha a dama pendurada e não cai na recaptura; cada técnica reduz os nós até profundidade fixa.

Partidas com `chess match` (`internal/match`), 3+0,03 por lado, 8 partidas ao mesmo tempo, pares de aberturas da lista embutida (46 linhas, cada uma com as duas cores):

```bash
make build
bin/chess match --engine1 bin/chess-engine --engine2 bin/chess-engine \
  --name1 null --name2 none \
  --option1 NullMove=true --option1 LMR=false --option1 Futility=false \
  --option2 NullMove=false --option2 LMR=false --option2 Futility=false \
  --tc 3+0.03 --concurrency 8 --pairs 2000 --sprt 0,10
```

O segundo teste liga `LMR` nos dois lados menos o base; o terceiro, `Futility`.

## Limites

- Os Elo são entre versões da própria engine, numa partida rápida (3+0,03). Contra outras engines e em tempos longos os ganhos tendem a ser menores, mas a ordem deve se manter.
- As três técnicas foram medidas uma vez, numa ordem só. O ganho do futility depois de null move e LMR não é o mesmo que ele teria sozinho.
- Os parâmetros (R, a fórmula da LMR, as margens 150/350) são os valores comuns da literatura, não ajustados. Ajustar cada um é trabalho para SPRTs com elo1 menor.
- Sem PVS, a LMR é a única busca com janela nula. Uma busca de variante principal deve somar mais e mudar o ganho das reduções.

## Conclusão

O critério foi atendido para as três. Elas ficam ligadas por padrão e continuam como opções UCI, para que a próxima mudança da busca possa ser medida da mesma forma (ver "Engine strength (SPRT)" em `docs/TESTING_GUIDE.md`).
